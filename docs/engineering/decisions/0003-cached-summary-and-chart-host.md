# ADR-0003：以已提交覆盖判断本地汇总就绪，复用现有绘制宿主

2026-10-24；状态：本轮采用，自审。关联 UI-003/004、腕温快速切换实测。

## 证据与边界

1.0.116 的物理触摸箭头基线为 6/18（较早 performClick 探针为 5/18）；后台读队列阻塞时，两组分别只有 1/6 按时呈现目标周。之前 8 项切换回归在每次操作后等待就绪，未覆盖快速连点，不能据此声称此场景已修复。

腕温仍等待 settled，后台校对结束前不接受已经可用的缓存。Vitals 又在每次接受数据后重新构造页面、日期栏和官方图表。本次目标为连续点击时日期/数据及时一致，不采用停止点击后再显示的防抖，也不把旧数据改成新日期。

## 决策

- 利用已有范围表与当前 scope 的关联，读取 `read_at>0` 的汇总覆盖，使用已有连续范围算法判断整个请求窗口是否已提交。freshness 和 coverage 分开；失效标记 0 不得视为完整。新增字段是只读快照元数据，无数据库迁移。
- 管理器共同校验设备、日期、时区和本地读完成；`HealthPageReadiness` 按 SUMMARY / OXYGEN_DAY 声明完整性。只迁移本次共享 Vitals 宿主；明细需求未知的其他页面不直接放宽为 locallyReady。
- 完整本地汇总可先显示，慢读继续校对；未覆盖的空缓存不能提前标成“暂无记录”。日期、数据、曲线同一次绑定，过期回调继续由现有代次和过渡控制拒绝。
- 复用活动可见期间的页面壳、日期栏和官方图表实例；模式改变只更新对应控件和数据。知识/记录内容仍局部重建，保留单位、缺失值、原始腕温与温差语义。停止页面后释放此宿主引用，下次先显示新初始状态再按当前身份绑定。
- 公共日期控件增加绑定入口并保持旧调用兼容；箭头从当前选择意图累加，标题仅随被接受的数据绑定。图表继续使用原版后端，重绑时清除旧高亮、重置视口和完成绘制相位。

1.0.117 触摸复测仍仅 13/18、15/18。后一次失败均为选择已收到、本地目标快照尚未完成，后台导入已结束。完整快照还扫描其他指标，所以为腕温声明 WRIST_SUMMARY 内容身份，沿用同一存储所有者、同一官方/原始投影，只读腕温。窗口相等、请求去重及失效重读包含内容身份；部分快照不能冒充完整快照。保持温差和原始值的先后覆盖规则。

## 验证与限制

先保存真实按钮基线，再以同一探针对照普通/慢读、120/180ms 连续前后点按，检查每次可见周、数据和根视图/图表实例。补充真实管理器的完整/不完整、错误设备/日期拒绝，以及范围 SQL 的 scope/失效隔离测试。

旧切换探针曾以“换了根视图”证明更新，现在改为检查目标数据和根视图复用，其他空态/位移/过期日期断言保留。保留血氧日明细完整性、月/周/空日期与首页回归；不以腕温通过代表全部卡片宿主已经迁移。
