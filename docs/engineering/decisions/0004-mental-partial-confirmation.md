# 0004：身心日汇总的部分确认

2026-10-27；用户已同意“先解决其他字段正常同步，再解决 HRV”。状态：1.0.128 部分确认与真实旧队列验收通过；HRV 完整云恢复仍未完成；自审。

## 依据与边界

2026-10-26 的真实只读核对中，24 条待确认记录的当前云版本以及 12 条无本地上传修订对照，原始响应均缺少 avgSleepHrv。24 条实际组包保留该字段，其余上传业务字段均匹配。见 analysis/mental-stat-audit-20261026/RESULTS.md。服务器是否实际保存平均值仍未知。

只允许 mental-stat 在 avgSleepHrv 确实缺失、原 payload 有非 null 平均值、其他实际上传字段和完整业务身份一致时 PARTIAL。显式 null、缺少其他字段、值不同、设备/日期不同、删除标记和非正版本均不能套用。严格 sameBusiness 不删除字段；其他流不允许部分匹配。

## 持久与提交

在既有 mutations_v2.state 增加 PARTIAL 语义，不新增官方表字段或数据库列。平均值及全部源 payload、修订、source_event、真实服务器版本保留。部分确认与 ACKED 明确区分；部分标记仅由原 CloudStore 事务所有者提交。

官方结构的 sync_status/updated 继续仅控制“是否还有待发送的本地投影修改”。仅当前修订且投影仍匹配被冻结 payload 时，部分确认可清除这两个发送标记，防止旧行被反复捕获。完整确认以权威队列状态和分类结果为准，不能用官方脏标记声称全部字段已确认；旧确认不得清除新修订或新本地编辑。

最新有效 PARTIAL 不进入发送选择和 pending/nativePending 计数，不单独触发后台续跑；独立计数并展示“部分确认，平均睡眠 HRV 保留本地、云端尚无法验证”。不得写完整成功时间。原 UNKNOWN/SENDING 仅在真实回读匹配后转换，不按版本号或 HTTP 成功批量改状态。

部分确认后，已严格核对的精确服务器版本可作为后续显式/原生修订的前序；仍验证实际业务字段与版本，不能借此绕过外部变更、旧导入版本或删除保护。新 HRV 单字段修改可保留为新的部分修订，不为无法验证的字段反复发送整条数据。

每轮正常增量回读后，有界检查最新有效 PARTIAL。若接口以后真实返回同身份、所有业务字段包括 HRV 均一致且版本有效，则只读升级 ACKED；不同值和缺失仍保留部分状态，不借旧修订清新编辑。

## 本地与导入

CloudStore 在当前有效部分确认存在时，不用云端平均 HRV 更新本地列，原始云响应仍完整保存供核对；缺失和 null 均不产生本地零值覆盖。其他字段沿用原身份、版本和脏值保护。

OfficialHistoryStore 的身心日汇总导入遵循官方合并中已核实的正值保留规则：输入的平均值为 null/非正占位、已有本地平均值为正时保留旧值；合法新正值仍按既有版本/身份规则合并。只修改这一列，不为其他指标扩散新默认规则。
