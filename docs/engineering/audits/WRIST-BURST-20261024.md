# 腕温快速切周修复与验收

2026-10-24，自审；关联 UI-003、UI-004、UI-007。原始基线 `analysis/wrist-burst-20261024/before.json`，变更 `docs/engineering/changes/20261024-wrist-burst.json`；全程保留原基线，未回滚既有未提交改动。

## 原因与变更

- 快速按键已被接收，但页面等待后台导入完成才呈现；即使数据已在本地，完整快照仍扫描心率、睡眠等无关指标。1.0.117 的诊断失败项显示选择已更新、本地读取未结束、导入已结束。
- `HealthPageReadiness` 与管理器校验当前日期、设备、时区和本地读取状态。腕温汇总有当前 scope 的连续已提交覆盖即可显示；未覆盖数据保持等待，不补造空记录。血氧日明细保留独立完整性判定。
- `HealthSnapshotWindow.Content.WRIST_SUMMARY` 声明精简读取内容。存储仍由同一所有者读取原有官方腕温、WRIST_INDEX、WRIST_RAW，沿用相同投影及覆盖优先级。内容身份参与窗口相等、请求去重、时区刷新和历史失效；新订阅者不接收未经其请求的部分快照。其他调用者继续使用 ALL。
- Vitals 复用页面壳、日期栏和官方图表，局部重绑内容。箭头从当前选择意图累加，标题、数据与曲线随同一被接受快照更新。保留原始腕温与温差的单位及缺基准语义。
- 共享日期栏和图表适配器保持旧调用兼容。本轮未迁移其他小卡宿主，台账仍保留其待办。

## 实测结果

固定同一手机和同一物理触摸注入操作序列，每组六次前后切周。每次触摸释放后等待 180ms（正常、阻塞导入各一组），120ms（阻塞导入一组），再核对该次目标。总计十八次，逐次验收，未仅检查最终日期。该等待时间不含触摸注入、16ms 按下时间及断言开销，不能当作严格固定的点击频率或逐帧基准。
