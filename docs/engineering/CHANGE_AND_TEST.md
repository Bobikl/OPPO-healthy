# 变更、审查和验证

## 执行顺序

1. 建立本次任务目录，阅读领域记录，确认工作区现状，不要求清空已有修改。
2. 修改前捕获基线。写变更记录，明确目标、契约、范围、影响和验收；跨所有权/持久格式变更增加决策记录。
3. 复现缺陷或建立新行为反例；实施单一目标的最小修改，同时核对公共消费者。
4. 自审实现和测试有效性；运行对应检查；用同一份修改前基线执行质量门禁。
5. 必要构建/实机/云验收分开执行，使用真实授权范围；保存产物哈希和结构化结果，清理本次临时内容。

范围失控时拆批或解释新增范围，保留原始基线及原因，不能重拍基线使意外改动消失。高风险调整必须先明确替代方案与回退；常规实现细节无需逐项请示。

## 可运行命令

以下 `<任务>`、`<记录>` 和 scratch 须替换为本次实际路径；scratch 先在 D 盘创建为任务专属目录。命令均在项目根目录执行。

```powershell
python -X utf8 standalone-relay/tools/quality_gate.py snapshot --out analysis/<任务>/before.json
python -X utf8 standalone-relay/tools/quality_gate.py check --baseline analysis/<任务>/before.json --change docs/engineering/changes/<记录>.json --out analysis/<任务>/gate.json --scratch D:\CodexData\scratch\<任务唯一目录>
& .\standalone-relay\build.ps1 -Baseline analysis/<任务>/before.json -ChangeRecord docs/engineering/changes/<记录>.json
```

`check` 从记录的 `required_checks` 执行固定入口：`self` 为门禁单元测试，`host` 为既有纯 Java 测试，`home` 为实际管理器加隔离存储/Android 边界及 SQL 测试。记录不能注入任意 shell 命令。运行时至少要求 `host`；D01 运行时变更另外要求 `home`；修改门禁本身必须要求 `self`。

门禁检查受管文件集合的新增、删除及内容变化，使用修改前指纹支持脏工作区；核对声明范围、编码、记录字段、固定检查退出码及检查期间意外源码变化。其受管范围见脚本 `FILES/TREES/SUFFIXES/SKIP`，不包括历史 APK、日志、真实数据库、生成目录和整个工作区的任意文件；触及范围外的源码/构建配置时必须先扩展受管范围并审查。

门禁只证明执行了哪些本地检查，不能证明设计正确、测试覆盖完整或真机行为正确。构建入口已在写 APK/递增版本前强制调用门禁及 self/host/home 完整检查；缺少记录、范围越界或失败均停止。本地工具仍可被有权限者修改绕过，未配置 Git 钩子或远端 CI。后续接入 CI 必须验证真实阻断能力，不能只写一份未启用配置。

## 按风险选择验证

| 变更 | 必要证据 |
| --- | --- |
| 文档/说明 | UTF-8 回读、路径与引用、范围审查；不构建 APK |
| 工具/验证脚本 | 成功和失败反例、错误/超时/部分失败的非零退出；记录对现有入口的影响 |
| UI/公共控制 | 本地状态/范围/取消检查、消费者矩阵；真机验证日期与数据一致、空态/加载、返回和布局；性能改动做同条件前后对照 |
| 存储/迁移/同步 | 合成隔离库事务、身份/代次、幂等、取消、冲突、游标与版本；实际 Android/真实云验证按授权单列 |
| 连接/通知/恢复 | 状态机、并发代次、超时/断开、权限变化及资源释放；必要真机，不干扰其他手机/项目 |
| 录音/原生/依赖 | 文件与生命周期、无效输入/容量、ABI/闭包/签名及设备行为；健康结果有效性单独验证 |

## 证据和通过含义

每条证据记录源码/产物标识、时间、环境、入口、断言、结果及限制。静态检查、隔离行为、Android 集成、真机交互、真实云写入/读取/合并分别归类。

Python/Java/JVM 退出为 0 仅说明该入口按设计完成；仍要审查入口是否真的拒绝失败。设备报告须校验 `status`、必需断言、完整用例数量、实际目标日期/版本，不接受只打印 JSON 的启动器。验证禁用 Python 优化模式，防止旧脚本的 `assert` 被移除。

“全部通过”须指明本次声明范围。记录 `deferred` 不能为空白地省略外部验收；若没有待验项，写空数组，其他情况明确未执行内容与原因。没有独立评审者时记录自审，不能填写虚构审批。

## 构建、发布与回退

现有 `standalone-relay/build.ps1` 是自定义编译/打包入口，不是 Gradle 项目。必须提供本次修改前的 `-Baseline` 和 `-ChangeRecord`，每次构建先通过完整本地检查。脚本和原生子构建默认使用 `D:\CodexData\scratch` 的唯一临时子目录；可用 `-TemporaryRoot` 显式指定绝对目录。子进程的 TEMP/TMP 也应使用任务 D 盘目录，保留必要工具缓存。

构建签名验证后保存 APK 的 `.build.json` 清单，包含实际版本、SHA-256 和构建前门禁路径，再递增下一版本号。清单/预检不证明实际安装、真机或真实云验收；相关结果单列。历史验证入口分类见 `standalone-relay/tests/README.md`。

任何发布/安装记录必须区分构建、签名验证、实际安装、运行验收。对外发布及真实云写入核对用户授权；不因门禁通过自动发布。不修改现有签名、包名、系统配置或用户数据来让测试变绿。

回退先分析数据格式与副作用。仅回退本批唯一修改和可再生产物，保留已有未提交代码、历史 APK、共享缓存、用户记录与唯一诊断资料。
