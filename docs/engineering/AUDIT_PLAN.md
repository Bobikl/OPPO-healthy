## 一批审查怎样结束

1. 列明入口、核心状态、生产者/消费者和持久化所有者，核对 [公共契约](ARCHITECTURE.md)。
2. 针对边界做代码核对与可重现反例；注明动态检查是否运行，不能仅以搜索无结果判定安全。
3. 问题登记稳定编号、严重度、具体证据、影响、整改边界和关闭条件。正向机制同样记录，避免重复重写。
4. 区分“审查完成”“已修复待验证”“已验证关闭”和“未审查”。无法穷尽的调用图/环境明确列为限制。
5. 修复另立有基线、范围和消费者矩阵的变更；检查通过才销项，避免一次审查顺带大改所有领域。

严重度按影响而非代码风格：P0 为已证实的严重数据/安全事故；P1 为数据正确性、身份隔离或核心功能重大失效；P2 为有界缺陷、性能/维护风险和验证缺口；P3 为低影响一致性/文档问题。未经验证的风险标明“待证实”，不直接套事故结论。
