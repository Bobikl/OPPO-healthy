# 独立版云同步实现与验收范围

版本：1.0.100。健康记录生产上传执行器已接通；逐项真实验收见 [CLOUD_UPLOAD_VERIFICATION.md](CLOUD_UPLOAD_VERIFICATION.md)。不同类型的实现范围、实际回读结果和未确认项目分别记录，不能据此认定全部官方云功能已经完成。

## 同步选择和触发

设备页的“数据云同步”包含总开关、8 个分类、“立即同步”和仅手动、充电、Wi-Fi、每日定时四种模式。仅手动置顶，每日定时置底并紧邻时间设置。总开关和分类默认关闭；关闭总开关隐藏下级选项。

开启分类只保存选择。充电与 Wi-Fi 等待下一次接入事件，每日定时等待下一设定时间，仅手动由“立即同步”发起。修改设置取消旧任务，过期设置版本的任务不能启动。已发起的任务按原网络/充电约束继续处理剩余 READY 队列，结果未知与冲突不单独触发无限重发。

连接事件由进程监听；通知转发服务运行时持续有效，进程完全终止期间的事件无法回放，重启只建立当前状态基线。账号退出、取消、设置变化与最终提交串行校验。结果展示异步保存，避免取消过程因状态落盘导致闪退。

## 手表新记录与旧历史的上行

OWW251 手表新收到的心率、活动分钟与活动日汇总已接入原生转换。账号会话、已成功认证的当前凭据、设备型号、导入历史所属账号和已知设备必须一致；来源事件与原始包在同一事务保存。不能在登录时把旧的、只有 MAC 的归档自动归给当前账号。

原始事件转换、不可变上传修订、本地投影和生产者检查点一并提交；重放使用原冻结修订。心率完整保留类型、可靠度和测量时间；活动使用官方单位、设备类型和冻结时区。活动日汇总按官方规则取累计值较大者，保留已知目标、推导完成标记，并使用该时区每日准确起止时间；未核实的目标或设备类型阻止对应转换，原始数据保留。

官方结构库中的旧记录只扫描当前账号且显式待同步的行。旧脏标记不能证明记录基于最新云版本编辑，版本不匹配或云基线变化即保留为冲突。空血糖日占位行不会被当成血糖测量上传。血氧、睡眠、身心等其他原生归档的上行转换仍待补齐，已核实的历史表上传不能代替这些原生转换。

## 云端确认与本地合并

首次采用单记录请求。发送前持久保存 SENDING，clientDataId 从持久 mutation ID 生成并跨重试稳定。写出前网络失败可回到 READY；明确服务器拒绝保留待修正，发送后超时或响应不明保存 ACK_UNKNOWN。缺少记录不能证明请求未写入，不自动重发。发送后未确认即停止该流；前一修订未知时，同一记录的后续修订不能发送或提前确认。

必须回读当前账号、相同业务身份与发送字段，并取得真实服务器版本，才能 ACK。修改时间字段按各 DTO 选择；服务器行版本缺失或为非正值时使用实际页面版本。睡眠 JSON 元数据按结构比较；睡眠日汇总按官方账号/日期聚合语义核对健康值，不把其来源设备注记当成聚合身份。可选睡眠心率和身心字段遵循官方校验，日照仅发送官方 DTO 字段。

同一身份只有精确匹配本应用已确认的前序服务器版本，才允许原生/显式修订延续；原生日汇总累计值还不能下降。外部变更及旧导入修订不能借此重置基线。较新修订已确认后，旧 READY 修订保存为 SUPERSEDED。

ACK 只清除对应本地修订，旧请求确认不清除较新编辑。合并保留本地 ID、较新值和未确认修改。删除标记不被旧记录恢复；冲突和结果未知保留并展示，不将 HTTP 成功直接视为同步成功。

作息和睡眠偏好只合并用户实际修改的字段，保留同组其他值，读回一致才清除对应待同步修订。设备 ACK 与云 ACK 分开。没有可靠归属的旧编辑不会自动归给未来账号。

## 验证和边界

1.0.100 构建、v3 签名及真机覆盖安装通过。60 项 Android 上传隔离检查、41 项合并隔离检查、23 项调度隔离检查和全部 37 个主机测试入口通过。隔离夹具的虚构值不上传官方云端；测试辅助进程、数据库及偏好独立隔离。

真实验收使用当前账号、应用 UID、生产请求/转换/保存方法与真实记录，核对上传回读和原有本地 ID。日志及可共享报告只记录类型、计数、布尔结果与协议错误代码，凭据、原始健康值及一致备份留在设备私有目录。

初轮测试中有 20 条较新的活动云汇总被旧导入脏值覆盖。已按用户明确批准的条件，检查仍为本次测试值及版本后，恢复测试前官方云原值；20/20 经逐条服务器回读确认。对应旧修订已阻止再次上传，版本守卫的入队和旧队列迁移路径均有隔离回归覆盖。

1.0.88 已验证 37 个注册流下载，其中 21 个非空、16 个空；当时各版本页均遍历，重复保存不新增重复记录。该结果属于下行验收，不能用于宣称所有类型上行完成。日历收起、身心与血氧显示等此前修复保留，详见 [SYNC_REVIEW_FIXES.md](SYNC_REVIEW_FIXES.md)。

以下范围仍需继续实现或独立验收：

- 全部原生手表类型的规范转换与逐类新记录上行；无真实记录的类型不得创建虚构健康值来凑验收。
- 剩余队列全部处理、未知回执的可靠对账，以及冲突处理。一次有界测试不代表历史队列已清空。
- 运动轨迹、鼾声音频/分析、健康档案文件及指标/复查计划等附件；元数据不代表附件恢复。
- 个人资料与目标上传，以及体重/体成分、血压、ECG、放松训练等未注册扩展类别。
- 屏幕熄灭、SDK 冷刷新、系统 Job 长时续传和双端并发的完整端到端验收。此次真实测试在前台及临时唤醒条件下进行，已观察到系统对后台 UID 的联网限制。
